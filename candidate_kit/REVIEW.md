# REVIEW.md

Review of the starter `app/main.py` (helpers and endpoints).

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `health()` | Returns `{"status":"ok"}` without touching MongoDB. | Point `MONGO_URI` at a dead server: `/health` still returns 200. Contract says 503 when MongoDB does not answer. | Run `client.admin.command("ping")` in a try/except and raise `HTTPException(503)` on failure. |
| 2 | Startup (no index code anywhere) | No indexes are created. Nothing enforces unique `emp_code` or unique `(emp_code, date)`, and list queries scan the whole collection. | `explain` on `/attendance` shows COLLSCAN; two parallel creates both succeed. | Create indexes idempotently at startup: unique on `employees.emp_code`, unique on `attendance_logs (emp_code, date)`, plus one matching the list query's filter and sort. |
| 3 | `MongoClient(...)` | Not `tz_aware`, so PyMongo returns naive datetimes. Subtracting them from aware values raises `TypeError`, and naive values are silently treated as local time. | Read a record back and call `.tzinfo`: it is `None`. | Pass `tz_aware=True` and convert at the boundary with small helpers (ms to aware UTC datetime, datetime to epoch ms). |
| 4 | `compute_late_minutes` (threshold) | `int(seconds/60) > 10` floors before comparing, so lateness between 10:00 and 10:59 after start returns 0. R2 says late when strictly more than 10:00. | Shift 09:30, punch-in 09:40:01: returns 0, expected 10. | Compare elapsed **seconds** with 600, and floor to minutes only after deciding the employee is late. |
| 5 | `compute_late_minutes` (time zone and date) | Builds `start` by `replace()` on the punch-in's own date and zone, not IST. Ignores overnight shifts (R1) and does not truncate sub-second values. | Overnight shift 22:00-06:00, punch-in at 02:00 IST: shift start is built on the wrong day. A punch-in with milliseconds is not truncated. | Truncate to whole seconds, convert to IST, and build `shift_start` on the **attendance date** from R1 (previous day for an overnight punch-in earlier than `shift_end`). |
| 6 | `compute_work_hours` | Uses float division and built-in `round()`, which is not half-up; microseconds are not truncated. | 28818 s = 8.005 h: float rounding can give 8.0, R4 expects 8.01. | Use `Decimal` built from integer seconds and `quantize(Decimal("0.01"), ROUND_HALF_UP)`, on second-truncated instants. |
| 7 | `compute_overtime` (rule) | Returns any positive minutes. R3 counts overtime only if it is at least 30. | Shift end 18:30, punch-out 18:45: returns 15, expected 0. | Return 0 when the floored minutes are below 30. |
| 8 | `compute_overtime` (date and tz) | Builds shift end from `date_str`, so overnight shifts end before they start. Setting `tzinfo=IST` while `punch_out` may be naive raises `TypeError` (a 500). | Overnight employee punching out at 06:10 next day: huge negative value clipped to 0. | Build shift end on the attendance date, add one day when `shift_end <= shift_start`, and work only with aware datetimes. |
| 9 | `EmployeeIn` | No validation: `emp_code`, `email`, `shift_start`/`shift_end` and `joined_on` accept any string, and `shift_start == shift_end` is allowed. A bad shift like `"9:30"` later crashes the helpers. | POST an employee with `shift_start: "abc"`: returns 201, and the first punch-in for them returns 500. Contract says 422. | Add Pydantic constraints from the OpenAPI schema (patterns, length limits, valid date) and reject equal shift times. |
| 10 | `PunchInIn.punched_at` | `Optional[int]` is lenient: floats and numeric strings are coerced, there is no range check, and `0` is treated as missing. Huge values crash `fromtimestamp` with a 500. | Send `1700000000.0`, `"1700000000000"`, or `99999999999999999`: not rejected with 422 as the contract requires. | Use `StrictInt` with min 100000000000 and max 4102444800000, and test `is None` instead of truthiness. |
| 11 | `PunchInIn.status` | Plain `str`, so `ABSENT`, `LEAVE` or `"banana"` are accepted on punch-in. | POST punch-in with `status: "ABSENT"`: returns 201 with a punch time. | Restrict to PRESENT, WFH, ON_DUTY (enum / Literal). |
| 12 | `create_employee` | Check-then-insert race: two parallel requests both pass `find_one` and both insert. | Fire two identical POSTs at once: two 201s. | Rely on the unique index and catch `DuplicateKeyError` to return 409. |
| 13 | `create_employee` (`created_at`) | `datetime.now()` is local, naive time, and is returned as a datetime/ISO string. Contract wants epoch milliseconds (stored as UTC). | Response `created_at` is a string, not an integer. | Store an aware UTC datetime and return epoch ms. |
| 14 | `list_employees` (skip) | `skip = page * page_size`: page 1 skips the first page. | With 5 employees and `page_size=20`, page 1 returns nothing. | `skip = (page - 1) * page_size`. |
| 15 | `list_employees` (total) | `count_documents({})` ignores the department filter. | Filter by department: `total` is still the whole collection (R10). | Count with the same filter used for the query. |
| 16 | `list_employees` (sort and bounds) | No sort, so order and paging are unstable. `page` and `page_size` are unbounded (negative skip, huge limits). | `page=0` gives a negative skip; `page_size=100000` is accepted. | `sort("emp_code", 1)`, and validate `page >= 1` and `1 <= page_size <= 100`. |
| 17 | `punch_in` (unknown employee) | `emp` can be `None`, so `emp["shift_start"]` raises `TypeError`. | Punch in with an unknown `emp_code`: 500, contract says 404. | Return 404 when the employee is not found. |
| 18 | `punch_in` (time and date) | `datetime.fromtimestamp(ms/1000)` uses the server's local zone, gives naive time with microseconds, and `date` comes from that local value instead of IST. No overnight rule (R1). | Run the server in UTC and punch in at 00:30 IST: wrong date is stored. | Convert ms to an aware instant truncated to seconds, derive the IST date with the overnight rule, and store the truncated value. |
| 19 | `punch_in` (race) | `find_one` then `insert_one`: two simultaneous requests both return 201. | Two parallel punch-ins for the same employee and day. | Insert directly and catch `DuplicateKeyError` from the unique `(emp_code, date)` index to return 409. |
| 20 | `punch_in` (response) | Adds an `id` from `_id`, which must never be exposed, and returns datetimes instead of epoch ms. | Response contains `id`, and `punch_in` is an ISO string. | Build the response from the contract fields only, converting times to epoch ms. |
| 21 | `list_attendance` (performance) | Loads every matching document into memory, sorts in Python and slices. No `date`/`emp_code` tie-break sort. | Slow and memory-heavy at 100k records; paging order unstable for same-date rows. | Use MongoDB `sort([("date", -1), ("emp_code", 1)])`, `skip`, `limit` and `count_documents`, backed by an index on the filter and sort fields. |
| 22 | `list_attendance` (validation and output) | No validation of `date_from`, `date_to` (format, `date_from` > `date_to`), `status`, `page`, `page_size`. Leaks `id`, and returns datetimes instead of epoch ms. | `date_from=banana` or reversed range returns 200; items contain `id`. | Validate with typed query parameters (422 on bad input), drop `_id`, and convert times to epoch ms. |

## Examined and judged not a defect
- `load_dotenv()` does not override variables that are already set, so real environment variables win, as the contract requires.
- Endpoints are plain `def` with the synchronous PyMongo client, so FastAPI runs them in its thread pool and they do not block the event loop.
- `create_employee` pops `_id` after `insert_one` (which adds it to the dict), so `_id` is not leaked there.
- The string comparison on `date` (`$gte` / `$lte`) in `list_attendance` is correct because `YYYY-MM-DD` sorts lexicographically in date order.
- The default shift times (09:30 / 18:30) match the contract.
